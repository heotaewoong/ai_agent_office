# 저장소 공개 범위

마지막 갱신: 2026-10-27 KST

이 저장소에는 콘텐츠 오피스 소스 코드, 테스트, 의존성 목록과 별도로 검토한 공개 문서를 올린다. 저장소 업로드는 콘텐츠 원고·출고·발송의 승인을 대신하지 않는다.

| 구분 | GitHub에 포함할 범위 |
|---|---|
| 앱 | 소스 코드·테스트·설정의 구조·설치 안내. 실제 키와 실행 데이터 제외 |
| 설계·벤치마킹 | 개인 정보와 비공개 자료 원문이 없는 공개 문서 |
| 사이트 | 검토한 통합 플레이북. 별도 저장소인 다른 Sites 프로젝트 제외 |
| 로컬 지식·조사·제작 | `database/`, `research/`, `output/` 전체 제외 |
| 개인 작업 지도·광고 기획 | 로컬 최종 문서 지도와 개인 광고 설계·실행 계획 제외 |

로컬 자료에는 유료 강의 원본·추출본, 회원 자료, 개인 드라이브 링크, 계정 정보와 공개 전 제작물이 섞여 있다. 파일명에 `PRIVATE`가 없는 복사본도 있으므로 해당 폴더 전체를 제외한다. `.gitignore`와 Git 추적 해제는 로컬 파일을 삭제하지 않는다.

환경 파일, 인증키·인증서, 브라우저 로그인 상태, 에이전트 개인 상태, DB·로그·백업 파일도 제외한다. 환경 변수 이름과 테스트용 예시는 실제 비밀값 없이 작성한다.

## 업로드 전 확인

1. `git status --short`와 `git diff --cached --stat`로 업로드 범위를 확인한다.
2. `git ls-files -ci --exclude-standard` 결과가 비어 있는지 확인한다. 결과가 있으면 제외 규칙에 걸리는 파일이 여전히 추적 중인 것이다.
3. 추가·수정할 파일에서 실제 인증키, 개인 드라이브 주소, 계정, 개인 경로와 비공개 원문을 검사한다. `.gitignore`는 파일 내용 자체를 검사하지 않는다.
4. 앱 코드를 올릴 때는 앱 안내의 백엔드·화면 검사를 실행한다.

## 이미 올라간 자료

제외 규칙 추가와 추적 해제는 새 커밋의 파일 목록에만 적용된다. 이미 공개된 과거 커밋의 파일은 별도로 이력을 정리해야 한다. 공유 이력을 바꾸는 강제 갱신은 저장소 소유자의 명시적 확인 후 수행한다.

실제 비밀키가 노출됐다면 해당 제공자에서 폐기·재발급해야 한다. 이력 정리도 다른 사람이 받은 복사본이나 플랫폼의 캐시 삭제를 보장하지 않는다.
