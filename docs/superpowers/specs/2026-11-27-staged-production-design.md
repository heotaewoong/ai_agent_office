# 나눠 만들기 설계 (2026-11-27)

## 문제
승인①에서 고른 결과물(블로그, 영상, 카드, PDF)을 한 번에 만들어서, 영상 비용이 승인 순간 자동으로 나갔다. 11/27 비용 기록: 영상 1편 약 2,700원(런웨이 클립 포함, 없이 약 340원), 카드뉴스 약 55원(배경 그림 포함 약 235원). 23개 작업 모두 영상을 골랐다.

## 결정 (사용자, 11/27)
승인① 뒤에는 블로그, 글 채널, 카드뉴스를 만든다. 영상은 그다음, 사람이 예상 비용을 보고 누를 때 만든다.

## 설계
- 규칙 하나: 영상과 다른 제작물을 같이 고르면 영상은 미룬다(`production_graph.staged`). 영상만 고르면 예전처럼 바로.
- `media.produce(defer_video=True)`: 같은 판본의 영상이 있으면 재사용, 없으면 `deferred`. 다른 출력의 재사용 규칙은 그대로.
- `production_graph.run_production`: LangGraph StateGraph `plan → text_outputs → video_gate → video_output`. 사람 결정의 기준은 Store의 produce 작업(`stage=video`), interrupt는 멈추는 자리, 재개 값은 작업 id.
- API: `POST /produce {"stage":"video"}`(완성본이 먼저 있어야 함, 이때만 유료 클립과 썸네일 그림 확인), `GET /production-estimate?stage=video`. 기본 예상 비용은 나눠 만들기면 영상 제외.
- 화면: 승인①의 영상 칸에 "블로그와 카드 다음에 비용을 보고 따로 만들어요", 제작·출고함에 "영상 만들기" 버튼(예상 비용 확인 포함).
- 기본 선택에 카드뉴스 추가(블로그, 영상, 카드).

## 하지 않은 것과 이유
- 승인 번호를 늘리지 않는다(⓪①②③ 의미 유지). 영상 클릭은 승인이 아니라 제작 요청이다.
- TimeoutPolicy, Send 병렬: README 2026-11-27 절의 이유.
- 출력별 판본 해시: 같은 선택을 유지하므로 지금 전체 판본 재사용으로 충분하다. 선택을 바꾸는 경우는 지금처럼 승인①을 다시 받는다.
