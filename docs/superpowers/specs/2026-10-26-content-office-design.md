# HeoBrain RSS 콘텐츠 오피스 구현 설계

구현 기준: 사용자가 2026-10-26에 제공한 상세 콘텐츠 파이프라인과 후속 답변. 작업 구간 02:20–08:20 KST, 외부 API 합계 10,000원 이하. 이 문서는 그 요청을 코드로 옮기기 위한 구체화다.

## 목표

공식 AI RSS에서 최신 항목을 수집하고 서로 다른 뉴스 3건을 선정한다. 출처·발행일·선정 이유와 함께 한국어 원고를 검토하고, 운영자가 원고를 승인하면 블로그와 YouTube Shorts를 제작한다. 게시와 전달은 최종 출고 승인 이후다. 블로그 공개는 영상 제작의 선행조건이 아니다.

완료 증거는 작동하는 로컬 웹 화면, 실제 수집 기록, 기사별 근거·원고·검수 기록, 승인 버전과 연결된 산출물, 관련 테스트와 브라우저 조작 기록이다. 전체 플랫폼 연결이나 수익성을 검증했다고 주장하지 않는다.

## 구성과 범위

- 기존 Markdown·참고 소스는 읽기만 한다. 신규 앱은 `apps/content-office` 아래에 둔다. 현재 폴더는 Git 저장소가 아니므로 기존 브랜치나 운영 사이트를 수정하지 않는다.
- 사용자의 명시 구조를 따른다: Next.js 검토 화면 → FastAPI → SQLite 작업 장부 → 별도 Python 작업자. 새 범용 에이전트 프레임워크는 추가하지 않는다.
- 실제 DB·자산·모델 캐시는 동기화 드라이브 밖 `~/.local/state/heobrain-content-office`에 저장한다. 환경변수로 임시 테스트 경로를 지정할 수 있다.
- 화면은 오늘의 뉴스, 콘텐츠 작업실, 제작·출고함, 운영 기록의 네 흐름이다. 입력·오류·비용·현재 단계·다음 행동을 항상 표시한다.
- 운영자 1명의 로컬 사용이 첫 대상이다. 서버는 loopback에 바인딩한다. 인증된 로컬 세션·Origin 검사를 통과한 사용자만 승인·편집·제작 요청을 보낼 수 있다. 원격 고객 서비스는 범위 밖이다.

## 데이터·처리 계약

1. RSS/Atom 공개 주소를 등록한다. 응답 크기·시간·리다이렉트·공개 호스트를 제한한다. 피드 실패와 기사 없음은 다른 상태다. 발행일 없는 항목·미래 날짜는 최신 기사 선정에서 제외한다.
2. URL 정규화와 같은 이벤트의 제목/출처를 비교해 중복을 묶는다. 최근 7일 우선이며 후보가 부족하면 실제 기간을 명시한다. 매번 3개가 없으면 부족 상태를 보여준다.
3. 선정 점수는 최신성·AI Agent/실용성·독자 가치·근거 신뢰성·영상 설명 적합성의 편집 기준이다. 모델 성능이나 클릭 성과를 측정한 점수가 아니다. 기사별 선정 이유와 제외 이유를 보존한다.
4. 원문에서 확인한 주장·숫자·기간·직접 URL·한계를 Evidence 항목에 저장한다. 외부 문서의 명령은 업무 명령으로 실행하지 않는다.
5. 모델 입력에는 원문과 독자 프로필·주제·실제 rubric·schema가 포함된다. Gen, Critique, Eval은 분리 호출한다. Critique와 Eval은 서로 답변을 받지 않는다. 수정 후 둘 다 새 원고에 재실행하며 Refine은 최대 2회다.
6. 캐시는 실제 합성 메시지·모델·옵션·rubric·schema·근거 버전으로 결정한다. 원고 변경은 새 버전을 만들며 이전 source/release 승인과 의존 미디어는 현재 버전에 사용할 수 없다.
7. 원고 승인①은 운영자·원고 해시·제작 선택·한도에 결속한다. 미승인·거절·옛 버전·중대 검수 오류가 있는 상태는 미디어 제작 전에 거부한다.
8. 제작은 글·영상·카드·PDF 선택별로 수행한다. 이번 필수는 티스토리 HTML/MD, 네이버 붙여넣기 텍스트, YouTube 제목·설명·말하기 대본·장면표·SRT·1080×1920 MP4·썸네일 5안이다. PDF는 근거 있는 요약·체크리스트 선택 출력이다.
9. TTS 성공 자산은 합성 전에 영속 저장한다. 실제 음성 길이를 ffprobe로 검사한다. 60초를 넘으면 임의 잘라내지 않고 대본 수정 대기로 반환한다. 자막 타이밍은 실제 장면 음성 길이에 연결한다.
10. 출고 승인②는 파일 해시·채널·계정·공개 범위·일정·상품 조건을 포함한다. 이번 기본 전달은 다운로드 가능한 수동 게시 패키지다. 외부 게시를 자동 완료로 표시하지 않는다. 업로드 연결은 사용 가능한 인증·정확한 승인 범위가 확인될 때만 수행한다.
11. 무료 PDF와 판매 상품은 분리한다. 운영 Marketplace의 검증된 상품 ID·캠페인 조건이 없으면 상품 연결을 생성하지 않는다. AI가 가격·쿠폰·다운로드 권한을 변경하지 않는다.
12. 작업은 영속 큐에서 claim 후 별도 프로세스로 처리한다. 재시작한 실행은 마지막 저장 결과를 조회하고, 결과 불명인 외부 호출을 자동 재송하지 않는다. 성공 자산·비용 예약·외부 ID를 보존한다.

## 비용

기존 연결된 API만 이용할 수 있으며 키를 UI·로그·산출물에 쓰지 않는다. 사용 전 `확정 비용 + 열린 예약 + 새 호출 최대 예상액 <= 10,000원`을 SQLite 트랜잭션으로 확인한다. 외화 요금은 버전과 적용 환산 기준을 표시한다. 환산 기준은 예산 예약용 보수적 가정이며 시장 환율로 표시하지 않는다. 알려지지 않은 모델 단가·결과 유실은 무료로 처리하지 않고 보류한다. 자동 유료 fallback은 없다.

## 이번 구현에서 정한 선택

사용자가 제공한 Next.js/FastAPI 구조와 기존 Python·FFmpeg 기능을 유지한다. Paperclip·Relevance·Sintra는 역할 분담·인계·회사 맥락을 설계에 반영하며 모두 설치하지 않는다. 총괄, RSS 연구, 편집, 비평, 평가, 영상, QA, 배포 준비, 마케팅의 전문 책임을 작업 기록에 남긴다. Hermes 연결은 같은 좁은 업무 API를 호출하는 선택 모듈로 두며 실제 설치를 가장하지 않는다.

## 검증

피드 파싱/날짜·중복, 원고 승인 우회·버전 변경, 모델 캐시/rubric, 최대 수정, 예산 동시 예약, 큐 재시작, 자산 보존, path traversal, 승인 주체·Origin, 불확실 상태, 실제 MP4·음성 길이를 검증한다. 브라우저에서 뉴스 선택→원고 보기→승인/거절→제작→다운로드를 실제 저장 상태와 대조한다.

운영자 승인이 없을 때 실제 기사 작업은 원고 검토 대기로 남는다. 미디어 기능은 별도로 승인된 합성 자료 테스트로 검증하며 이를 뉴스 제작 완료로 세지 않는다.
