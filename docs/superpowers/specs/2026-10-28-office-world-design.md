# HeoBrain 오피스 월드 설계 (3D 메타버스 관제 공간)

작성 2026-10-28 · 참고 자료: OneDrive 공유 폴더의 `CnvMatrixV1`(여백) 1~8단계 스냅샷 분석(2026-10-27), 사용자가 제시한 아이소메트릭 AI 오피스 참고 이미지, 기존 설계 `docs/superpowers/specs/2026-10-26-content-office-design.md`, `2026-10-27-ai-content-agent-design.md`

## 1. 결정

콘텐츠 오피스의 작업 상태를 **우주에 떠 있는 하나의 블록 땅 위 마을**로 보여주는 정적 웹 공간을 만든다. 땅은 1m 큐브(윗면 잔디, 옆면 흙, 아래 돌)를 쌓은 마인크래프트식 지형이고, 가장자리는 울퉁불퉁하게 깎인 채 우주에 떠 있다. 방 하나가 오피스의 단계 하나이고, 중앙 광장에는 공유 기억(뇌)이 있으며, 광장과 방 사이는 돌 블록 길로 이어진다. 블록형 캐릭터가 땅 위를 걸어 다니고, 사용자는 **걷기 시점**(3인칭, 마인크래프트식 조작)과 **관제 시점**(위에서 비스듬히 보는 디오라마) 중 하나로 본다.

처음 설계는 섬 다섯 개를 다리로 잇는 구성이었으나 2026-10-28 검토에서 "다리가 공간 낭비"라는 판단으로 이어진 땅으로 바꿨다.

이 공간은 **보여주는 쪽**이다. 승인(⓪ 기획 선택 · ① 원고 · ② 출고 · ③ 회차)은 콘텐츠 오피스 앱에서 사람이 하며, 이 공간은 승인을 만들거나 대신하지 않는다. 화면 어디에도 "자동 게시됨"을 표시하지 않고, 출고 승인 뒤의 상태는 "수동 전달 대기"로 적는다.

`CnvMatrixV1`의 코드는 작성자 동의가 확인되지 않았으므로 가져오지 않는다. 그 프로젝트에서 **구조만** 참고한다. 구역(폴더) 하나가 건물 하나, 공간 중앙의 기억 모형, 앱이 읽기 전용 투영 API(`goals`, `agentIds`)를 내놓고 공간이 그것을 읽어 배치하는 방식, 공간을 만드는 아키텍트와 공간 안에서 일하는 에이전트의 분리가 그것이다.

## 2. 범위

- 포함(1차): 정적 사이트 `sites/office-world/`. 우주 배경, 떠 있는 섬 5개, 중앙 뇌, 다리, 블록 캐릭터, 두 시점, 섬 카드·뇌 카드·이벤트 자막·미니맵·작업 목록 패널, 투영 데이터 파일과 같은 모양의 실시간 API 읽기, EC2 정적 배포 안내.
- 제외(1차): 콘텐츠 오피스 백엔드의 투영 API 구현(2차), 실제 AI 엔진 세션을 캐릭터로 띄우는 실행 서비스(3차), 여러 사용자 동시 접속, 음성, 로그인, 공간 안에서의 승인 조작.
- 유지: 승인 단계의 의미와 사람 결정. `database/learning-private/`, `database/class101/`, `PRIVATE` 자료는 투영 데이터에 넣지 않는다.

## 3. 공간 구성

| 요소 | 모습 | 데이터 출처 |
|---|---|---|
| 우주 | 별이 흐르는 어두운 하늘, 은은한 성운 색 | 고정 |
| 블록 땅 | 1m 큐브 지형. 광장·방·길은 높이 0의 평지, 나머지는 0~2칸 높낮이와 블록 나무. 가장자리 아래로 흙·돌 블록이 쌓여 떠 있는 청크처럼 보임 | 고정(방 배치에서 계산) |
| 중앙 광장 "공유 기억" | 돌 원판 광장, 가운데 빛나는 구와 회전하는 고리 | `brain.notes`, `brain.sources` |
| 방 5개 | 지붕 없는 방: 두 벽(단계 색, 안쪽은 어두운 톤), 어두운 나무 바닥, 단계색 러그·소파, 책상·모니터·의자·램프·식물·책장 | `stages[]` |
| 길 | 광장에서 각 방 입구로 깔린 돌 블록 길과 양쪽 발광 띠. 작업이 단계를 넘어갈 때 점이 흘러감 | `flows[]`, `events[]` |
| 캐릭터 | 머리·몸·팔·다리 상자로 만든 블록형. 책상에 앉거나, 광장(기억)까지 걸어갔다 돌아옴 | `agents[]` |
| 플레이어 | 같은 블록형이되 밝은 색. WASD·방향키 이동, Shift 달리기, Space 점프, 한 칸 계단 자동 오르내림. 벽·책상은 통과하지 않음 | 로컬 입력 |

방의 기본 다섯 단계는 콘텐츠 오피스 파이프라인을 따른다.

| 방 | 오피스 화면 | 사람 결정 |
|---|---|---|
| 오늘의 뉴스 | 공식 RSS 후보, 기획 은행 | ⓪ 기획 선택 |
| 원고 작업실 | 근거, 원고, 별도 비평·평가 | ① 원고 승인 |
| 제작 스튜디오 | 음성·장면·자막·MP4, 카드, PDF | 영상 검토 |
| 제작·출고함 | 썸네일 선택, ZIP 패키지 | ② 출고 승인, ③ 회차 |
| 운영 기록 | 큐, 예산, 재시도, 성과 스냅샷, 교훈 | 교훈 승인 |

방의 개수·이름·색은 데이터가 정한다. 코드에 단계 이름을 고정하지 않으며, 데이터에 방이 늘면 광장 둘레에 같은 간격으로 배치하고 땅도 그에 맞춰 다시 생성한다. 여섯 개 이상이면 방이 서로 닿지 않도록 광장과의 거리를 늘려야 한다(현재 상수, 후속 보완).

## 4. 시점과 조작

- **관제 시점(기본)**: 비스듬히 내려다보는 고정 각도의 궤도 카메라. 마우스 드래그 회전, 휠 확대, 섬 클릭으로 오른쪽 패널 열기. 모든 카드가 보인다.
- **걷기 시점**: 플레이어 뒤를 따라가는 3인칭 카메라. 섬과 다리 위에서만 이동할 수 있고 가장자리 밖으로는 나가지 않는다. 섬 가까이 가면 그 섬의 카드만 보이고, 캐릭터 가까이(약 3m)에서 E를 누르면 담당 작업 요약이 뜬다.
- **M** 또는 화면 버튼으로 시점 전환. R은 플레이어 뒤로 카메라 복귀.
- 휴대폰: 관제 시점만 제공하고 터치 드래그·핀치로 조작한다. 걷기 시점은 숨긴다.

## 5. 화면 위 정보(HUD)

HTML 오버레이로 그린다. 3D 좌표를 화면 좌표로 투영해 매 프레임 위치를 맞춘다.

- **섬 카드**: 단계 이름, 작업 수, 배정 동료 수와 실행 중 수, 사람 승인 대기 수. 클릭하면 패널.
- **뇌 카드**: "공유 기억 · 3,192절 · 원본 111편"처럼 데이터 값 그대로.
- **작업 패널(오른쪽)**: 선택한 섬의 작업 목록. 제목, 상태(후보·조사 중·비평 중·사람 승인 대기·제작 중·출고 승인·수동 전달 대기·실패), 담당. 오피스 앱 링크가 있으면 "오피스에서 열기"를 새 탭으로.
- **자막 띠(아래)**: 최근 이벤트를 한 줄씩. 예: "원고 작업실이 '…' 원고 v2를 비평에 보냈습니다."
- **상단 바**: 오피스 이름, 데이터 갱신 시각, 연결 상태(예시 데이터 / 실시간), 시점 버튼.
- **미니맵(오른쪽 아래)**: 섬 사각형, 허브, 동료 점, 플레이어 점.
- **모델 태그(왼쪽 아래)**: 현재 동료들의 엔진·모델 이름 묶음.

## 6. 데이터 계약: 공간 투영 v1

공간은 아래 JSON 하나만 읽는다. 1차는 `data/space.json` 예시 파일, 2차는 콘텐츠 오피스 백엔드가 같은 모양으로 `GET /api/space`를 제공한다. 주소는 페이지 쿼리 `?api=<URL>` 또는 전역 `window.OFFICE_WORLD_API`로 주며, 실패하면 예시 파일로 돌아가고 상단 바에 "예시 데이터"라고 표시한다.

```json
{
  "version": 1,
  "generatedAt": "2026-10-28T09:00:00+09:00",
  "office": { "name": "HeoBrain 콘텐츠 오피스", "url": "http://localhost:3110" },
  "brain": { "name": "공유 기억", "notes": 3192, "sources": 111, "label": "과거 기획·근거" },
  "stages": [
    { "id": "inbox", "name": "오늘의 뉴스", "approval": "⓪ 기획 선택", "color": "#f0a040",
      "url": "http://localhost:3110/news",
      "items": [ { "id": "job-1", "title": "…", "state": "candidate", "stateLabel": "후보", "needsHuman": true, "agentId": "a1" } ] }
  ],
  "agents": [
    { "id": "a1", "name": "수집 담당", "engine": "Codex", "model": "gpt-5-codex", "stageId": "inbox",
      "status": "running", "task": "RSS 후보 12편 발행일 확인" }
  ],
  "events": [ { "time": "09:12", "stageId": "scripts", "text": "원고 작업실이 '…' 원고 v2를 비평에 보냈습니다." } ],
  "flows": [ { "from": "scripts", "to": "creative", "itemId": "job-2" } ]
}
```

- `agents[].status`는 `running` · `idle` · `waiting`(사람 답 대기) · `error`. 공간은 이 값만 해석하고 추론하지 않는다.
- `items[].needsHuman`이 참이면 카드에 "사람 승인 대기"로 센다.
- `flows[]`는 최근 단계 전이이며, 다리 위를 흐르는 점으로만 쓴다.
- 투영에는 제목·상태·담당 이름만 넣는다. 원문, 비밀값, 비공개 자료 경로는 넣지 않는다.
- 실시간 모드에서는 10초마다 다시 읽고, 바뀐 항목만 애니메이션으로 반영한다. 폴링 실패는 마지막 상태를 유지하고 상단 바에 표시한다.

## 7. 연출 규칙

- 동료 캐릭터는 자기 섬의 책상이 기본 자리다. `running`이면 모니터가 켜지고 머리 위 점이 깜빡인다. `waiting`이면 노란 물음표, `error`면 붉은 표시.
- 예시 데이터 모드에서는 동료가 가끔 허브까지 걸어가 기억을 확인하고 돌아오는 연출을 한다. 실시간 모드에서는 `events[]`에 "기억" 관련 이벤트가 있을 때만 걷는다. 연출은 상태를 꾸미지 않는다. 데이터에 없는 진행률·완료를 만들지 않는다.
- `flows[]` 하나마다 점 하나가 해당 다리를 한 번 흐르고 사라진다.
- 모션 줄이기 설정(`prefers-reduced-motion`)이면 별 흐름·고리 회전·걷기 연출을 멈추고 상태 표시만 남긴다.

## 8. 기술

- Babylon.js 7.54.0(cdnjs, 고정 버전) 하나만 쓴다. 모델 파일 없이 모든 형태를 코드로 만든다. 글꼴은 Google Fonts(Noto Sans KR, IBM Plex Mono)이며 실패 시 시스템 글꼴.
- 파일: `sites/office-world/index.html`, `styles.css`, `app.js`, `data/space.json`, `README.md`. 빌드 도구 없음. 어떤 정적 서버에서도 열린다.
- 상태는 `app.js` 안의 모듈 네 개로 나눈다. `data`(읽기·폴링·검증), `world`(장면·섬·다리·캐릭터), `hud`(오버레이·패널·미니맵), `controls`(입력·카메라). 모듈은 `space` 객체 하나를 공유하고 서로의 내부를 건드리지 않는다.
- 비밀값 없음. 브라우저 저장소에는 마지막 시점 선택만 둔다.

## 9. 배포(EC2)

- Nginx 또는 S3 정적 호스팅에 폴더 그대로 올린다. 필요한 것은 HTML·CSS·JS·JSON 다섯 파일과 CDN 접근뿐이다.
- 실시간 모드는 오피스 백엔드의 `/api/space`를 같은 도메인 아래 리버스 프록시로 노출하고(`/api/space` → 백엔드 8510), 그 외 API는 노출하지 않는다.
- HTTPS는 EC2 앞의 ALB 또는 certbot. 투영 데이터에 비공개 정보가 없어야 공개 주소에 올릴 수 있다.

## 10. 검증

- `node --check app.js`로 문법.
- Playwright Chromium으로 페이지를 열어 콘솔 오류 없음, 섬 카드 5개와 뇌 카드 표시, M 키로 시점 전환, 섬 클릭 시 패널 열림, 1366×768과 390×844에서 가로 넘침 없음을 확인하고 화면을 저장한다.
- 예시 데이터에서 "게시됨"·"자동" 같은 단어가 카드·자막에 없는지 문자열 검사.

## 11. 다음 단계

1. 콘텐츠 오피스 백엔드에 `GET /api/space` 투영 구현(2차 설계).
2. 동료 캐릭터를 실제 AI 세션에 연결하는 실행 서비스 검토(3차). 이때 `CnvMatrixV1` 코드 사용 여부는 작성자 동의로 결정한다.
3. 섬 안 가구와 캐릭터의 외형 교체(glTF 저폴리 에셋), 낮·밤 테마.
