# 3D 오피스 월드: 참고 프로젝트 조사와 설계 결정

작성 2026-10-28 · 결과물 [설계서](../docs/superpowers/specs/2026-10-28-office-world-design.md) · [구현 계획](../docs/superpowers/plans/2026-10-28-office-world.md) · [정적 사이트](../sites/office-world/README.md) · 상세 노트 [research_notes/3D 오피스 월드/](../research_notes/3D%20오피스%20월드/)

## 1. 결론

콘텐츠 오피스를 위한 3D 메타버스 공간은 **참고 프로젝트의 코드가 아니라 구조만 가져와 직접 구현**한다. 참고 프로젝트(이하 CnvMatrixV1)는 "3D 공간 + AI 코딩 CLI를 동료 캐릭터로 + 폴더 하나가 건물 하나"라는 형태가 우리 목표와 거의 같았지만, 외부 강의 자료로 공유받은 것이라 라이선스가 확인되지 않았고, 에이전트가 OS 격리 없이 전체 권한으로 도는 로컬 개인용 설계라서 공개 EC2에 올릴 산출물의 기반으로 쓰기 어려웠다.

가져온 것은 네 가지 규약이다. (1) 구역·건물을 폴더와 선언 파일로 자동 발견하는 방식, (2) 앱이 읽기 전용 투영 API(목표·담당 동료 ID)를 내놓고 공간이 그것을 읽어 배치하는 방식, (3) 공간을 만드는 아키텍트와 공간 안에서 일하는 에이전트를 지침 파일로 분리하는 방식, (4) 공간 중앙의 공유 기억 모형. 이를 콘텐츠 오피스의 승인 단계(⓪ 기획 선택 · ① 원고 · ② 출고 · ③ 회차)에 맞춰 "공간 투영 v1" 데이터 계약으로 다시 정의했다.

1차 결과는 Babylon.js 정적 페이지 하나다. 우주에 떠 있는 마인크래프트식 블록 땅 위에 중앙 광장(공유 기억)과 오피스 단계별 방 다섯 개가 돌 블록 길로 이어져 있고, 관제 시점과 걷기 시점을 오간다. 승인은 오피스 앱에서 사람이 하며 공간은 상태를 보여주기만 한다.

## 2. 참고 프로젝트 CnvMatrixV1 요약

공유 폴더에는 2026-09-08부터 10-05까지 8단계 스냅샷(zip 8개, 약 5.6GB)이 있었다. 코드 자체는 단계당 1MB 미만이고 나머지는 의존성·로컬 LLM 실험 파일·브라우저 바이너리·실험 로그다. 단계별 변화는 다음과 같다.

| 단계 | 핵심 변화 |
|---|---|
| 1 | Babylon.js + TypeScript 3D 공간. 관찰 카메라만 |
| 2 | 3인칭 캐릭터, Codex 에이전트를 동료로 생성·대화. 독립 실행 서비스와 SQLite 등록부 |
| 3 | Codex·Claude Code·Antigravity·Kimi 멀티 엔진, 앱 안 터미널 "아키텍트" |
| 4 | 루트 `AGENTS.md`와 `World/` 작업 폴더 분리 |
| 5 | World 웹앱 연결 규약 v1(`app.json`). 앱 폴더가 공간의 건물로 자동 표시 |
| 6 | 첫 World 앱 "목표 지도", 집단기억(`brain`) 설계 시작 |
| 7 | 집단기억 구현(SQLite, 용어 사전·기억 그래프·회상·활용 피드백), PM·작업자·검수자 멀티에이전트 실증, 로컬 LLM 실험 |
| 8 | macOS 이식, 더블클릭 실행 파일, Tailscale 원격 접속 |

구조는 세 층이다. **여백 앱(루트)**: 3D 공간, 채팅, xterm.js 터미널. 브라우저 → Vite 게이트웨이 → 독립 Node 실행 서비스 → 엔진별 프로세스. **아키텍트**: 프로젝트 루트에서 공간 자체를 설계·구현하고 `World/AGENTS.md`로 에이전트 규율을 관리. **World 에이전트**: `World/` 안에서만 사용자 요청을 수행하고 웹앱을 `World/apps/<앱>/`에 만든다.

주의할 점은 셋이다. 라이선스 파일이 없고 작성자 동의가 확인되지 않았다. 에이전트가 `approvalPolicy=never`, `sandbox=danger-full-access`로 실행되고 World 폴더 범위는 관습일 뿐 강제가 아니다. Node 24.18 이상, node-pty 네이티브 빌드, Windows의 PowerShell C# 컴파일이 필요하며 작성자는 Windows ARM64(Parallels)와 Mac에서만 검증했다. 자세한 디렉터리 구조와 규약 원문 요약은 [연구 노트](../research_notes/3D%20오피스%20월드/cnvmatrix-structure.md)에 있다.

## 3. 참고 이미지와 재료의 대응

사용자가 제시한 아이소메트릭 AI 오피스 이미지(방마다 기능, 중앙 THE BRAIN, 방 카드, 흐르는 길, 자막, 미니맵)는 기존 재료와 거의 1:1로 대응했다.

| 이미지 요소 | 콘텐츠 오피스 · CnvMatrixV1 대응 |
|---|---|
| 방마다 하나의 기능 | 파이프라인 단계: 오늘의 뉴스 → 원고 작업실 → 제작 스튜디오 → 제작·출고함 → 운영 기록 |
| 중앙 THE BRAIN "shared memory" | 오피스의 과거 지식 111편·3,192절 검색, 또는 CnvMatrixV1의 `brain` 집단기억 |
| 방 카드 "3 agents · 1 running" | 실행 서비스의 동료 목록과 실행 상태 |
| 캐릭터가 길을 따라 방으로 이동 | 투영 규약의 목표·담당 동료 ID 배치를 방 단위로 적용 |
| "scheduled ✓" 카드 | 승인 ②·③ 상태. 앱은 자동 게시를 하지 않으므로 "출고 승인 완료 · 수동 전달 대기"로 표기 |
| 하단 자막 | 운영 기록의 이벤트 스트림 |
| 길 위를 흐르는 점 | 큐에서 작업이 단계를 넘어갈 때의 상태 전이 |

이미지는 걷는 메타버스가 아니라 "관제 디오라마"에 가까웠다. 사용자는 두 가지를 모두 원했으므로(위에서 보는 관제 화면과 마인크래프트식으로 걸어 다니는 캐릭터), 한 Babylon.js 장면에 두 카메라를 두는 "한 세계, 두 시점"으로 설계했다.

## 4. 두 경로와 선택

| 경로 | 장점 | 단점 |
|---|---|---|
| A. CnvMatrixV1 코드를 호스트로 쓰고 오피스를 World 앱(건물)으로 등록 | 실행 서비스·터미널·멀티 엔진이 이미 있어 빠름 | 작성자 동의 필요, Python 백엔드를 Node 런처로 감싸야 함, 보안 자세가 공개 배포에 부적합, 무거운 환경 의존성 |
| B. 규약만 가져와 자체 Babylon.js 정적 페이지로 구현 | 라이선스 문제 없음, 빌드 도구 없이 EC2 정적 호스팅, 데이터 계약만 맞추면 어떤 백엔드든 연결 | 실행 서비스·실제 AI 세션 연결은 이후 단계에서 별도 구현 |

사용자가 EC2 정적 배포를 명시했고 작성자 동의가 없었으므로 **B**를 택했다. 실제 AI 세션을 캐릭터로 띄우는 3차 단계에서 A의 코드 사용 여부를 다시 결정한다.

## 5. 세션 중 설계 변경 이력

| 순서 | 사용자 피드백 | 반영 |
|---|---|---|
| 1 | 화질이 좋지 않다 | 장치 픽셀 비율만큼 렌더 해상도 상향(최대 2배), MSAA 4배 + FXAA, HUD 좌표 환산 |
| 2 | 다리가 길어 공간 낭비 | 허브-방 거리 36m → 23m, 카메라 기본 거리 조정 |
| 3 | 땅이 따로 떠 있지 말고 달 표면처럼 이어진 마인크래프트 땅이면 좋겠다 | 섬·다리를 없애고 1m 큐브 지형 한 덩어리로 교체(잔디·흙·돌, 가장자리 침식, 블록 나무). 길은 돌 블록 + 발광 띠. 걷기는 땅 어디나 가능, 한 칸 계단 자동 |
| 4 | 방 안이 너무 하얗고 안 예쁘다 | 어두운 나무 판자 바닥, 단계색 러그·소파, 벽 안쪽 어두운 패널, 호두나무 책상, 중앙 광원 완화 |
| 5 | 방을 클릭하면 확대해서 들어가게 | 클릭 시 카메라가 방으로 이동·확대, 패널의 "걸어서 들어가기"로 입구에 서서 걷기 시점 진입, "전체 보기"로 복귀 |
| 6 | 나가기도 있게 | 걷기 시점에 "공간에서 나가기" 버튼(현재 방 이름 표시), Esc 동일 |

## 6. 검증

문법 검사, 예시 데이터 검사, 금지 문구("게시됨", "자동 게시") 검사, Edge(Playwright) 1366×768·390×844 화면 검사로 콘솔 오류 0건, 방 카드 5개와 뇌 카드 표시, 패널·시점 전환·확대·들어가기·나가기 동작, 가로 넘침 없음을 확인했다. 헤드리스 검사 환경은 초당 2~3프레임이라 이동이 느리게 보였는데, 이동 가능 판정은 정상이었고 실제 GPU에서는 문제없다. 느린 PC를 위해 프레임당 이동 한도를 0.1초로 늘렸다.

## 7. 다음 단계

1. 콘텐츠 오피스 백엔드에 `GET /api/space` 투영 구현(2차 설계). 제목·상태·담당 이름만 넣고 원문·비밀값·비공개 자료 경로는 넣지 않는다.
2. 동료 캐릭터를 실제 AI 세션에 연결하는 실행 서비스 검토(3차). CnvMatrixV1 코드 사용 여부는 작성자 동의로 결정.
3. 방 수가 여섯 개 이상일 때 광장과의 거리를 자동으로 늘리는 계산, 가구·캐릭터 외형 교체, 낮·밤 테마.
4. 협업자 연결 방법은 [sites/office-world/README.md](../sites/office-world/README.md)의 "다른 UI와 연결하기"를 따른다.
