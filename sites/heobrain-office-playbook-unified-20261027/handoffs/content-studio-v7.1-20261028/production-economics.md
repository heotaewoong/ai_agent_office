# HeoBrain 콘텐츠 자동화: 제작경로와 수용 1편 원가 선택

- 작성일: 2026-10-28 KST
- 문서 상태: v7.1 보강 제안. 실제 생성시험 0회·유료 API 호출 0회·계정 연결 0회·발행 0회. 한국어 품질 비교는 미실행이다.
- 기준 문서: [통합 가이드](master-guide.md), [제작품질 평가설계](quality-evaluation.md)
- 범위: 설명교육·브랜드형·생성이야기형의 모델 선택, 실제 운영에서 기록할 비용 입력, 가정 손익분기. 기존 Site·운영 설정은 수정하지 않았다.

## 1. 먼저 고를 것

콘텐츠 제작은 요리와 비슷하다. 사용한 재료 가격에 버린 재료와 다시 만든 시간을 합쳐야 한 접시의 비용이 보인다. 여기서는 검수를 통과한 영상 한 편을 그 한 접시로 본다.

처음에는 **설명교육 경로를 기본 운영안**으로 잡는다. 실제 설명 화면·직접 그린 도식·명확한 내레이션을 먼저 만들고, 브랜드를 보여 줄 필요가 있는 편에서만 영상 생성 장면을 더한다. 이야기를 감상시키는 콘텐츠는 별도 경로로 관리한다. 서로 다른 목적의 세 경로에 같은 예산이나 같은 품질 점수를 적용하지 않는다.

현재 오피스의 기본 제공자는 Gemini이고 음성 프로필은 Windows Heami·Gemini Kore로 확인되어 있다. 아래 Sonnet·ElevenLabs·Runway는 **도입 후보를 정한 설계 기본안**이다. 기존 연결을 바꿨다는 뜻이 아니다. 현재 조합을 기준선으로 남기고, 같은 입력과 검수 기준을 통과한 후보만 바꾼다.

| 현재 구현 | 이번에 검증 완료 | 계획/제안 | 미구현/차단 |
|---|---|---|---|
| 기존 오피스의 기획·초안·승인·출력·패키징 구조는 통합 가이드의 소스 감사 범위를 따른다 | 이 문서에서 사용하는 공식 단가·라이선스 조건을 다시 확인하고 계산식의 산술을 로컬 Node.js로 검산했다 | 경로별 후보와 전환 조건, 수용 원가 장부, 손익분기 비교를 제안한다 | 실제 생성 품질·계정 접근·청구액·실제 전환율·모델 우승자는 확인하지 않았다 |

## 2. 세 제작경로 선택표

| 제작경로와 목적 | 기본안: 새 모델을 시험할 때의 구성 | 대체안과 선택 이유 | 도입 조건 |
|---|---|---|---|
| **설명교육**: AI 기능 설명, 실습, 옵시디언·에이전트 사용법, 뉴스 해설 | 글: Sonnet 5.5 초안 + 분리된 검토. 시각: 실제 허가된 실습 화면·자체 HTML/SVG, 필요한 정지화만 Nano Banana 2.1. 음성: Multilingual v2 후보. 영상: 기존 Remotion 또는 HyperFrames 템플릿 하나와 FFmpeg | 현재 Gemini·Heami·Kore를 유지하는 경로를 반드시 비교한다. Qwen3-TTS는 로컬 자원·음성 권리·속도·발음 검증 후 후보로 추가한다. 움직임이 설명을 돕는 단일 장면만 생성 영상으로 바꾼다 | 숫자·날짜·부정 표현의 음성 오류 없음, 화면과 대본 일치, 도식의 정확한 한국어, 수정시간이 기준선보다 개선되어야 한다. 화면 녹화와 자막으로 설명이 되면 새 영상 모델은 도입하지 않는다 |
| **브랜드형**: HeoBrain 소개, 제작 과정, 실제 상품·쿠폰 안내 | 글: Sonnet 5.5의 브랜드 브리프. 이미지: Nano Banana 2.1의 참조 이미지. 영상: 핵심 3개 장면 이내에서 Runway Gen-4.5 후보. 음성: 설명 중심이면 v2, 감정·대화가 기획의 핵심일 때 Eleven v4 후보. 썸네일: 내부 문구안에서 고른 뒤 Nano+자체 SVG 또는 AutoKliq | 동일 ShotSpec을 통과하면 Gen-4 Turbo로 비용을 줄이는 실험을 한다. Midjourney는 아트 방향 탐색을 위한 수동 제작 후보이며 공식 자동화 허용 여부와 별개로 다룬다. 기존 이미지·브랜드 템플릿 재사용도 비교한다 | 제품·쿠폰 정보는 실제 서버 스냅샷과 일치해야 한다. 브랜드 참조·인물·폰트·음원 권리를 확인한다. 생성 영상이 사실과 다른 제품 기능을 보여 주면 탈락한다. AutoKliq는 월 수용 썸네일 수와 실제 수정시간 절감으로 결정한다 |
| **생성이야기형**: 허구 시나리오, 캐릭터 설명극, 감상형 이야기 | 글: Sonnet 5.5로 이야기·인물 설정·샷 명세를 분리. 이미지: Nano Banana 2.1 참조 시트. 영상: Runway Gen-4.5 후보. 음성: Eleven v4 대화 후보, v2 내레이터 대체. 합성: 기존 렌더러+FFmpeg | 캐릭터·가림·동작·참조 제어에서 부족한 지점만 Kling 또는 Luma로 짧게 비교한다. 반드시 필요한 고유 3D 장면만 Blender로 만든다. 예산이나 연속성이 실패하면 정지화+모션+내레이션으로 바꾼다 | 같은 인물·소품의 연속성, 가림 전후 형태, 대사 화자 구분, 허구 표시, 음성 동의가 필요하다. 샷 폐기와 수동 편집시간의 변동이 크므로 편당 상한과 중단 조건을 먼저 정한다 |

여기서 “기본안”은 한국어 품질이 이겼다는 판정이 아니다. Sonnet 5.5·Nano Banana 2.1·Gen-4.5·Eleven v4의 공식 제품·API 정보가 존재하는 것과 HeoBrain 계정에서 접근 가능하고 좋은 결과가 나오는 것은 별도 확인 사항이다.

### 경로별 첫 편의 범위

| 경로 | 먼저 만들 작은 단위 | 다음 단계로 넘어갈 증거 | 비용이 늘 때 먼저 줄일 것 |
|---|---|---|---|
| 설명교육 | 한 가지 행동을 설명하는 원고, 자체 도식, 1분 안팎의 영상 1편 | 동일 사실을 원문·화면·음성이 일관되게 설명하고, 처음 보는 사람이 행동을 재현함 | 불필요한 이미지 변형과 생성 장면. 정확한 자막·설명 검수는 유지 |
| 브랜드형 | 실제 가치 하나를 보여 주는 소개 1편, 핵심 장면 3개, 썸네일 1개 | 실제 제품 정보와 일치하며 브랜드 일관성을 통과하고, 재제작 사유가 기록됨 | 전체 영상을 생성하지 말고 핵심 장면만 유지. 썸네일은 문구 5개를 먼저 고르고 렌더 수 제한 |
| 생성이야기형 | 같은 캐릭터·소품이 있는 짧은 이야기 1편 | 장면 연결과 음성 화자가 유지되고, 폐기 테이크를 포함해 편당 상한 안에 듦 | 등장인물·장면 수·복잡한 카메라 동작. 부분 수정으로 복구 안 되면 정지화 경로로 전환 |

## 3. 도입을 결정할 평가 규칙

품질 평가는 기존 평가설계의 중립 한국어 대본·동일 3개 샷·TTS 20문장을 재사용한다. 도구마다 유리한 장면을 골라 한 표에서 비교하지 않는다.

1. **기준선을 남긴다.** 현재 Gemini·Heami/Kore·기존 렌더러의 모델·설정·대본·실제 시간·비용을 기록한다.
2. **실패 원인에 맞는 후보 하나만 더한다.** 글 수정이 오래 걸리면 글 모델, 캐릭터가 흔들리면 영상, 발음이 틀리면 음성 후보를 비교한다.
3. **필수 검수를 먼저 통과한다.** 사실·권리·숫자·부정 표현·상품 정보·음성 동의 실패를 미감 점수로 상쇄하지 않는다.
4. **수용 원가와 수동 수정시간을 함께 본다.** 새 모델이 API 단가가 낮아도 사람이 더 고치면 도입하지 않는다. 단가가 높아도 총원가가 내려가면 후보가 된다.
5. **적은 표본의 한계를 적는다.** 세 샷 두 번씩은 초기 탈락 여부를 보는 시험이다. 그 결과를 일반적인 성공 확률이나 전체 콘텐츠 우승자로 발표하지 않는다.
6. **전환은 예산·승인 범위 안에서 한다.** 새 유료 제공자로 자동 우회하지 않는다. 모델·가격·입출력·권리 또는 장면이 바뀌면 해당 범위를 다시 확인한다.

권장 운영 결정 예시: “필수 검수를 통과하고, 별도 승인된 초기 시험 묶음에서 수용 1편 총원가와 수정시간을 모두 기록한 뒤 전환 판단”으로 둔다. 몇 퍼센트 개선이면 바꿀지는 사업 목표에 맞춘 운영 정책이며 이번에 실측한 기준이 아니다.

## 4. 비용 입력표: 실제로 무엇을 기록할까

**수용 1편**은 정해진 필수 검수와 해당 출력 승인을 통과한 버전이다. 업로드 성공·조회수·주문 발생은 다른 지표다. 원가는 콘텐츠 작업을 시작한 시점부터 실패와 재작업까지 포함한다.

| 입력 | 반드시 남길 실제 값 | 빠뜨리기 쉬운 비용·구분 |
|---|---|---|
| 글 모델 | 기획·초안·검토·수정·메타데이터의 실제 입력/출력 토큰, 캐시 읽기·쓰기, 도구 호출 | 한국어 글자 수를 임의로 4로 나눠 토큰으로 쓰지 않는다. 검색·도구·추론 출력 과금과 반복 호출도 기록 |
| 이미지 | 모델·크기·실제 생성/수용/폐기 수, 입력 토큰, 텍스트/생각 출력, 편집·참조 입력 | “수용 이미지 3장”만 기록하면 버린 생성물 비용이 사라진다. 동일 자산 재사용과 새 과금 생성 구분 |
| 영상 | 모델·경로·해상도·음성 유무·입력 영상, **과금된 원본 출력 초**, 수용 초, 생성 횟수 | 6초 생성 후 5초만 사용해도 과금은 해당 모델의 원본 기준. 입력 영상 가산·최소 생성량·환불/실패 과금 확인 |
| TTS | 실제 요청별 과금 문자·음성·모델·언어·재생성 이유, 생성/수용 길이 | 원고가 350자여도 재녹음이 있으면 과금 문자는 더 많다. 부분 수정은 연결 문맥 때문에 해당 조각 전체를 다시 만들 수 있음 |
| 렌더·파일 | 실행 횟수·소요 시간·자원, 저장 GB·월, 다운로드/전송, 임대 자원 | 무료 소프트웨어도 자원·저장·운영 비용은 존재. 실패한 렌더가 성공한 유료 이미지·음성까지 다시 생성하지 않게 함 |
| 사람 시간 | 조사·사실 확인·시청/청취·수정·복구의 실제 활동 분, 업무를 못 한 대기 분 | 자유롭게 다른 일을 한 무인 대기 시간을 작업시간으로 전부 더하지 않는다. 실제 생산을 막은 대기만 따로 평가 |
| 고정비·도입 | 새 구독·라이선스·비공유 도구 비용, 설정/이관 시간, 이미 지출한 비용과 신규 비용 | 포함 크레딧을 월 구독료에 배분한 뒤 같은 사용량을 또 현금 비용으로 더하지 않는다 |
| 수용 결과 | 시작한 작업 수, 수용 편수, 중단/폐기 편수, 승인 버전·해시 | 성공한 편의 기록만 남기지 않는다. 공통 조사비를 블로그·영상·뉴스레터 각각에 전액 중복 계상하지 않음 |

## 5. 수용 1편 원가 계산식

### 5.1 사용량 환산액

```text
글 환산액 =
  비캐시 입력토큰 × 입력단가
  + 캐시 읽기/쓰기별 토큰 × 해당 단가
  + 출력토큰 × 출력단가
  + 검색·도구 등 별도 요금

생성 환산액 =
  모든 이미지·영상·TTS 시도의 해당 요금표 금액
  - 실제 확정 환불액

사용량 환산액 =
  글 환산액 + 생성 환산액 + 렌더/저장/전송 + 외부 자산 사용료
```

입력 단위가 백만 토큰이면 백만으로, 천 문자이면 천으로 나눠 계산한다. 구독 크레딧은 사용량을 비교하기 위해 환산할 수 있지만 **환산액이 추가 현금 청구액과 같다는 뜻은 아니다.**

### 5.2 현금 원가와 시간 포함 총원가

```text
기간 수용 1편 현금 원가 =
  (기간 실제 변동 청구액 + 해당 기간 신규 고정비 + 실제 자원/자산 비용)
  / 기간 수용 편수

기간 수용 1편 시간 포함 총원가 =
  기간 수용 1편 현금 원가
  + (조사·검수·수정·복구·실제 업무 차단 시간 × 시간당 평가액) / 수용 편수
  + 도입 비용의 합의된 수용 편수별 배분액

도입비 배분 =
  (일회성 결제 + 설정/이관 활동시간 × 시간당 평가액) / 배분할 수용 편수
```

현금 지출을 비교하는지, 이미 보유한 도구의 사용량을 비교하는지, 사람 시간을 포함한 사업 원가를 비교하는지 표 제목부터 구분한다. 원화는 실제 결제 환율·세금·수수료로 환산한다. 이 문서는 환율이나 사용자의 시간 가치를 추측하지 않는다.

### 5.3 폐기율과 수용률은 다르다

```text
자산 폐기율 d = 폐기한 생성 자산 수 / 생성한 전체 자산 수

계획 단계의 예상 생성 횟수 = 필요한 수용 자산 수 / (1 - d)
```

이 예상식은 수용 가능성이 일정하고 독립적이라는 단순 가정이다. 캐릭터 오류가 반복되는 실제 작업에서는 성립하지 않을 수 있다. 실행 후에는 예상식 대신 **실제 시도 횟수와 실제 과금**을 쓴다. 길이가 서로 다른 영상은 횟수 폐기율 외에 과금 초 대비 수용 초를 함께 본다.

전체 콘텐츠 수용률은 “수용 편수 / 시작 편수”다. 영상 테이크 폐기 비용을 이미 시도 장부에 포함했다면, 같은 폐기율을 총액에 또 곱하지 않는다. 완성 작업 자체가 중단된 비용은 기간 장부에 한 번 포함하고 실제 수용 편수로 나눈다.

- 아래는 **사용량 환산액+가정 사람 시간** 비교다. 신규 구독 고정비·도입비·세금·환율·음원/외부 자산·검색/grounding·별도 업스케일·판매/발행비는 제외한다.

### 7.4 중단한 편까지 포함하면

가정한 생성이야기 작업 10편에 각각 위와 같은 자원·사람 시간을 썼지만 8편만 수용됐다고 가정한다.

```text
10편의 사용량 환산액 = 10 × 15.1869 = $151.869
10편의 가정 사람 시간 = 10 × 25 = $250
수용 1편 시간 포함 원가 = (151.869 + 250) / 8
                         = $50.23
```

$40.19에 폐기 테이크는 이미 포함되어 있다. 여기에 같은 테이크 폐기율을 다시 곱하지 않는다. 8/10은 이 예시의 전체 작업 수용률이며 실제 운영 확률이 아니다.

블로그·뉴스레터를 함께 만들 때는 공통 조사·주장 검수·승인 원고 비용을 한 번 기록하고, 채널별 문맥 수정·디자인·발행 검수의 추가 비용만 더한다. 회계상 배분 기준을 정해도 공통 비용 총합은 한 번이어야 한다.

## 8. 손익분기 비교 1: 더 비싼 영상 모델이 유리한 경우

다음은 **같은 5초 장면 4개가 필수 검수를 통과했다는 가정**이다. 서로 다른 해상도·표현력·동작 결과는 품질 평가에서 먼저 확인해야 한다. 시도 횟수·폐기·수정시간은 실측이 아니다.

| 가정 | Gen-4 Turbo | Gen-4.5 |
|---|---:|---:|
| 원본 생성 시도 | 5초×8회 | 5초×5회 |
| 수용 장면 | 4개 | 4개 |
| 횟수 폐기율 | 50% | 20% |
| 영상 API 환산액 | 40초×$0.05 = $2.00 | 25초×$0.12 = $3.00 |
| 사람 활동 수정시간 | 16분 | 10분 |
| $20/시간 가정 평가액 | $5.33 | $3.33 |
| 이 비교 범위 합계 | **$7.33** | **$6.33** |

이 가정에서는 Gen-4.5의 영상 사용액이 $1 높지만 수정이 6분 줄어 합계가 약 $1 낮다. **추가 API 비용 $1의 시간 손익분기는 3분**이다.

```text
필요한 수정시간 절감(분) =
  추가 API 비용 / 시간당 평가액 × 60

$1 / $20 × 60 = 3분
```

이관·설정에 4시간이 추가로 들어 평가액 $80이 발생한다고 가정하면 편당 $1 절감으로 **80편에서 초기 비용을 회수**하고 그 이후에 이익이 난다. 한두 번 잘 나온 장면만 보고 기존 시스템을 바꾸지 않는 이유다. 실제 우승자와 절감액은 아직 없다.

## 9. 손익분기 비교 2: AutoKliq 구독을 추가할까

AutoKliq Core 공식 월 구독에 포함된 크레딧을 썸네일 1개당 2회 렌더에만 쓴다고 가정한다. 다른 기능이 크레딧을 쓰지 않을 때 월 수용 썸네일은 최대 50개다. 실제로 연구·수정 등에서 소비하면 더 적어진다. 무료 플랜·일회성 무료 팩은 이 반복 구독 예시에서 제외한다.

비교용 작업시간은 다음과 같이 **가정**한다.

- Nano 1K 이미지 2회+자체 SVG 문구 편집: 12분. 이미지 입력600토큰·텍스트/생각 출력300토큰. 사용량 $0.07035/수용 썸네일.

- 두 방식 모두 썸네일의 실제 정확성·브랜드·가독성 검수는 통과했다고 가정한다. 클릭률 향상을 보장하지 않는다.

```text
자체 방식 시간 포함 비교 원가 = 0.07035 + 12/60 × 20
                              = $4.07035 / 수용 썸네일

AutoKliq 비교 원가 = 25 / 월 수용 썸네일 수 + 4/60 × 20

월 손익분기 N =
  25 / (0.07035 + (12 - 4)/60 × 20)
  = 9.13... → 최소 10개
```

| 월 수용 썸네일 수 | 자체 방식 가정 총원가/개 | AutoKliq 가정 총원가/개 | 판단 범위 |
|---|---:|---:|---|
| 10개 | $4.07 | $3.83 | 이 가정에서 구독비를 회수함 |
| 30개 | $4.07 | $2.17 | 포함 크레딧·수정시간 가정이 유지돼야 함 |
| 50개 초과 | $4.07 | 단순식 적용 중단 | 공유 크레딧 부족·추가 플랜/과금부터 확인 |

초기 연결·양식 설정에 2시간=$40이 추가된다는 가정이면 첫 달 회수할 금액은 $65다. 같은 조건에서는 **최소 24개**가 첫 달 손익분기다. 이미 결제한 구독의 단기 추가비 비교와 새로 구독하는 결정은 계산을 분리한다.

**월 $25와 렌더당 약 $0.25를 동시에 더하면 포함 크레딧을 이중 계상한다.** 새 구독을 결정할 때는 월 고정비를 실제 수용 수로 배분하고, 포함량 초과와 다른 기능의 크레딧 소비를 따로 기록한다. 이 문서는 구독·채널 연결·실제 썸네일 변경을 실행하지 않았다.

## 10. 손익분기 비교 3: Remotion 비용 때문에 옮길까

Remotion Free License의 자격은 개인/조직 구조 등 실제 조건으로 먼저 판정해야 한다. 가격 페이지의 “3명 이하” 문구만 보고 HeoBrain의 적용 자격을 확정하지 않는다. 자격이 있다면 이 절의 월 $100 비교는 적용되지 않는다.

자격이 없는 자동화 조직에서 현재 공개 구조를 단순화하면 다음과 같다.

```text
월 자동화 라이선스 비용 = max($100, $0.01 × 과금 렌더 수)
```

수용 영상당 2번 렌더하고 월 5,000편 이하라면 10,000렌더 이하이므로 이 예시는 월 최소 $100 구간이다. 과금 렌더의 정확한 정의와 실패/미리보기 취급은 도입 전 적용 계약에서 확인한다.

**가정:** 기존 Remotion 템플릿을 유지하면 HyperFrames 이관안보다 수용 영상당 사람 작업이 5분 적고, 비교용 시간 평가액은 $20/시간이다. 이관비·자원비 차이는 우선 제외한다.

```text
편당 유지 편익 = 5/60 × 20 = $1.6667
월 최소 비용 회수 편수 = 100 / 1.6667 ≈ 60편
```

이 가정에서는 월 60편이 월 최소 비용과 시간 편익이 같아지는 지점이다. 이보다 적다고 바로 이관하라는 뜻은 아니다. 이관·회귀 검수·기존 템플릿 재작성 시간을 더하고, 실제 자격과 렌더 수를 확인해야 한다.

HyperFrames의 Apache-2.0 저장소 라이선스에는 위와 같은 편당 소프트웨어 과금이 없지만, 실제 실행 자원·외부 자산·의존성 조건까지 0원인 것은 아니다. [HyperFrames 공식 저장소](https://github.com/heygen-com/hyperframes)

## 11. 운영 우선순위와 중단 기준

| 우선순위 | 결정 | 기록할 증거 |
|---|---|---|
| 1 | 현재 조합으로 설명교육 1편의 수용 장부부터 완성 | 원문·원고 승인·실제 음성 길이·정확성 검수·모든 생성 시도·수정시간 |

| 3 | 브랜드형의 핵심 장면만 추가 | 실제 상품 사실, 참조 자산 권리, 생성 원본 초와 수용 초 |
| 4 | 생성이야기형은 별도 작은 실험 묶음 | 캐릭터·화자 연속성, 중단 테이크 비용, 편당 상한 |

운영 정책으로 미리 정할 항목은 “총 예산 상한”, “장면당 최대 유료 시도”, “시간 초과 시 정지화 전환”, “권리·사실 오류 시 중단”, “새 제공자 사용 승인”이다. 숫자는 실제 제작 목표와 사용자가 승인한 예산으로 채운다. 이번 문서의 예시 금액을 자동 한도로 사용하지 않는다.

판매 전환까지 평가할 때는 서버의 실제 결제·쿠폰·환불 자료로 주문당 순기여이익을 별도 산출한다. 결제액에 이미 반영된 쿠폰 할인을 또 비용으로 빼지 않고, 무료 주문은 매출 0으로 기록한다. 콘텐츠 제작비 회수 주문 수는 “캠페인 비용 / 검증된 주문당 순기여이익”으로 계산하되, 양의 기여이익·실제 귀속·반품 조건을 확인하기 전 예상 매출로 쓰지 않는다.
