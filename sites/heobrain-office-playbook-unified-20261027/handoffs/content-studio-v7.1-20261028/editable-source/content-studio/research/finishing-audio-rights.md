# HeoBrain 콘텐츠 자동화: 자막·음향·자산 권리의 후반작업

- 조사일: 2026-10-28 KST
- 상태: 공식 문서 조사와 운영 설계 제안. 실제 자막·음향 처리와 자산 확보는 미실행.
- 실행 횟수: 모델 설치 0회, 음원·영상 다운로드 0회, 외부 개인 음성 전송 0회, 유료 호출 0회.
- 변경 범위: 이 Markdown 문서 1개만 새로 작성. 기존 Site·원본 35개 도구 ID·운영 설정은 수정하지 않음.
- 적용 원칙: 승인 원고와 출처가 사실의 기준이다. ASR은 실제로 들린 말과 시간을 검토하는 보조 도구이며 사실 확인자가 아니다.

## 1. 먼저 선택할 후반작업 경로

영상의 후반작업은 발표회 준비와 비슷하다. 발표 원고, 발표자가 실제로 말한 내용, 화면 자막, 배경음악을 맞춰야 한다. 자막이 맞아 보여도 음성이 다른 숫자를 읽었다면 발표 자체를 고쳐야 한다.

**기본안은 승인 원고 → TTS → 실제 길이 확인 → 문장 자막 → 청취 검수 → 필요한 경우에만 단어 정렬 → 음향 믹스 → 최종 재검수**다. ASR·정렬·배경음악을 모두 항상 추가하지 않는다.

| 상황 | 먼저 선택 | 추가 도입 조건 | 이번 확인 상태 |
|---|---|---|---|
| 설명교육·단일 내레이터 | 승인 원고의 문장 단위 자막과 실제 음성 청취 | 문장 경계를 잡기 어려울 때 faster-whisper CPU 후보를 시험 | 구현·실행 전 제안 |
| 쇼츠·단어 강조 | 문장 자막을 먼저 승인 | 단어 강조가 이해에 필요하고 언어별 정렬 품질·자원을 통과하면 WhisperX 선택 시험 | 한국어·본 PC 성능 미실측 |
| 브랜드 소개 | 원고·상품 사실·발음 확인, 적은 효과음 | 권리 확인된 BGM이 설명을 돕는 경우에만 추가 | 실제 음원 선정 없음 |
| 생성이야기·여러 화자 | TTS에서 이미 확정한 화자별 트랙과 장면을 유지 | 자연 녹음에서 실제 화자 구분이 필요할 때만 diarization 검토 | 다중 화자 모델·약관·정확성 미검증 |
| 여러 채널로 배포 | 무음/BGM 없는 마스터와 권리 확인된 채널별 믹스 | 각 음원의 허용 채널·재사용 조건을 확인한 뒤 파생본 제작 | 계정 연결·외부 발행 없음 |

## 2. 자막·정렬 도구의 좁은 비교

| 후보 | 공식적으로 확인한 역할 | 저메모리 PC에서의 선택 | 라이선스·추가 조건 | 도입 판단 |
|---|---|---|---|---|
| **OpenAI Whisper** | 다국어 음성 인식·음성 번역·언어 식별. 코드와 모델 가중치는 MIT | 원형 비교 기준. 한국어에는 다국어 모델을 선택하며 영어 전용 `.en` 모델과 구분 | 사용하는 배포판·의존성도 확인. 모델 크기별 GPU VRAM 표를 CPU RAM 보장으로 옮기지 않음 | 이미 설치되어 있고 충분히 검수되었다면 재사용 후보. 이번 설치·실행 없음 |
| **faster-whisper** | CTranslate2 기반 Whisper 재구현. CPU의 `compute_type="int8"` 경로가 공식 예제에 있음 | **우선 시험 후보:** 다국어 base/small 중 작은 모델부터, 한 작업씩 짧은 음성으로 측정. 메모리가 부족하면 실행 대기 | 저장소 MIT. 실행 엔진·모델 버전·언어·스레드·VAD 설정을 기록 | 속도보다 실제 한국어 누락·환각·수정시간과 최대 RAM을 먼저 비교 |
| **WhisperX** | ASR 뒤 언어별 음소 모델을 이용한 강제 정렬, 선택적 화자 분리 | 기본 상시 구성에서 제외. 단어 강조가 필요한 편만 선택 시험. CPU int8 경로는 존재하지만 정렬 모델도 추가로 사용 | 본 저장소 BSD-2-Clause. 정렬 모델·화자 모델의 라이선스와 이용 조건은 별도. 현재 화자 분리 안내에는 Hugging Face 토큰·모델 약관 수락이 있음 | 숫자 표기·고유명사·겹침 발화·화자 오류를 사람이 확인할 수 있을 때만 사용 |

근거: [Whisper 공식 저장소](https://github.com/openai/whisper), [faster-whisper 공식 저장소](https://github.com/SYSTRAN/faster-whisper), [WhisperX 공식 저장소](https://github.com/m-bain/whisperX), [WhisperX 라이선스 원문](https://raw.githubusercontent.com/m-bain/whisperX/main/LICENSE).

### 메모리와 배치에 관한 주의

faster-whisper 저장소의 **다른 시험 장비**에서 small CPU int8은 RAM 1,477MB, 배치 크기 8의 int8은 3,608MB로 기재되어 있다. 이는 본 PC의 요구량이나 처리속도 보장이 아니다. 저메모리 환경에서는 배치를 크게 묶는 것이 메모리 절감책이 되지 않을 수 있다. 이번 제안의 “배치 처리”는 작업을 대기열에서 **순차 처리**한다는 뜻이며 모델 내부 batch size를 높인다는 뜻이 아니다. [공식 벤치마크와 CPU 예제](https://github.com/SYSTRAN/faster-whisper)

현재 여유 RAM은 이 조사에서 다시 측정하지 않았다. ASR·TTS·영상 모델·렌더러를 동시에 상주시킨다는 가정도 하지 않는다. 첫 시험 때 실제 최대 RAM·스왑·처리시간을 재고, 진행 중인 AI 작업의 응답성이 나빠지면 대기시킨다. 단순히 모델이 CPU를 지원한다는 이유로 저메모리 적합성을 통과시키지 않는다.

### 강제 정렬도 정답 보증은 아니다

WhisperX는 정렬 사전에서 표현하지 못하는 숫자·통화 표기 등에 시간이 붙지 않을 수 있고, 겹치는 발화·화자 분리에도 한계가 있음을 명시한다. 한국어의 모든 어절·숫자가 정확히 정렬된다고 가정하지 않는다. [공식 한계 설명](https://github.com/m-bain/whisperX#limitations-)

Whisper 공식 모델 카드도 실제 발화에 없는 문구를 생성하는 현상과 언어·억양별 성능 차이를 설명한다. 무음에 생긴 문구나 ASR이 매끈하게 바꾼 숫자를 사실 근거로 올리지 않는다. [Whisper 모델 카드](https://github.com/openai/whisper/blob/main/model-card.md)

## 3. 승인 원고에서 자막까지: 단계와 산출물

| 순서 | 작업 | 남길 산출물 | 통과 기준 |
|---|---|---|---|
| 1 | 원문 근거·숫자·상품 정보를 검토한 표시용 원고 승인 | 원고 버전·해시·근거 ID | 승인되지 않은 주장 추가 없음 |
| 2 | 표시 원고와 TTS 발음용 문자열을 구분 | 표시 문구 ↔ 발음 사전 ↔ 문장 ID 대응표 | 의미·숫자·부정 표현 보존 |
| 3 | 허용된 음성으로 TTS 생성 | 모델·음성·설정·청크 순서·음성 해시 | 화자 동의·권리와 해당 생성 예산 충족 |
| 4 | **생성된 음성 파일의 실제 길이** 확인 | 스트림/파일 정보·실제 샘플 길이·쉼 구간 | 글자 수로 길이를 확정하지 않음 |
| 5 | 승인 원고에 문장 시작·종료를 배정 | 문장 자막 초안 | 사용한 타임스탬프가 같은 음성 해시에 대응 |
| 6 | 필요한 경우 ASR 결과와 비교하거나 강제 정렬 | ASR 보조본·정렬 결과·불일치 목록 | 원고를 ASR 문구로 조용히 교체하지 않음 |
| 7 | 숫자·고유명사·부정 표현을 원문·음성·화면으로 대조 | 청취 검수 기록 | 중요한 오류가 남지 않음 |
| 8 | 자막 길이·줄바꿈·표시 위치를 편집 | SRT 또는 WebVTT, 렌더용 자막 | 모바일에서 실제 읽기 확인, 마지막 자막이 영상 밖으로 나가지 않음 |
| 9 | 필요한 BGM·SFX를 권리 선별 후 믹스 | 트랙별 원본·믹스 설정·자산 원장 | 설명 가청성과 권리 검수 통과 |
| 10 | 최종 영상의 자막·음성·믹스를 다시 확인 | 최종 파일 해시·채널별 검수 기록 | 인코딩·속도·컷 변경 뒤에도 동기 유지 |

`ffprobe`는 컨테이너·스트림 정보를 기계 판독 가능한 형식으로 확인하는 도구다. 메타데이터만으로 실제 청취를 대신하지 않는다. 최종 렌더에서도 길이·오디오 시작 시각·샘플레이트·채널을 다시 확인한다. [ffprobe 공식 문서](https://ffmpeg.org/ffprobe.html)

TTS 제공자가 해당 요청에서 검증 가능한 타임스탬프를 돌려주면 우선 재사용 후보로 삼는다. 모든 모델·API가 이를 제공한다고 가정하지 않는다. 다른 음성이나 이전 생성본의 타임스탬프는 재사용하지 않는다.

### 숫자 표기의 예시

다음은 개인정보 없는 **설계 예시**이며 실제 청취 결과가 아니다.

| 구분 | 예시 |
|---|---|
| 표시 원고 | “2026년 10월 28일 기준이며, 자동 발행은 하지 않습니다.” |
| 발음용 문자열 | “이천이십육 년 시월 이십팔 일 기준이며, 자동 발행은 하지 않습니다.” |
| 반드시 확인 | 연도·월·일, “하지 않습니다”의 부정 의미 |
| 오류 처리 | 음성이 날짜나 부정을 틀리면 해당 TTS를 수정하고 관련 정렬·믹스·렌더를 갱신 |
| 금지할 처리 | 화면 자막만 맞게 두고 잘못 읽은 음성을 통과시키거나, ASR이 바꾼 날짜를 새 사실로 채택 |

원고 자체의 사실이 틀렸다면 원문 검토와 원고 승인을 먼저 갱신한다. 발음 오류만 고치면 영향받은 음성·자막·믹스·출력 범위를 다시 검수한다. 영향이 없는 원문 근거까지 무조건 다시 수집하지 않는다.

## 4. 자막 검사 항목

다음은 HeoBrain에 제안하는 내부 검수 항목이다. 특정 플랫폼의 공식 자막 길이 규정이라고 주장하지 않는다.

- 문장 ID와 승인 원고가 일치하고, 의도한 발음 표기 외의 생략·추가가 없는가.
- 날짜·버전·가격·쿠폰·수량·소수점·단위·고유명사·부정 표현을 실제로 듣고 확인했는가.
- 타임코드가 유한한 숫자이며 시작 < 종료이고, 편집 의도가 없는 역전·겹침·긴 공백이 없는가.
- 오디오의 시작 오프셋·청크 사이 쉼·속도 변경을 반영했는가.
- 한글 줄바꿈이 의미를 끊지 않고, 세로 영상의 얼굴·핵심 화면·플랫폼 UI에 가리지 않는가.
- 작은 휴대폰 화면에서 읽을 수 있는 노출 시간을 확보했는가. 글자 수만으로 통과시키지 않았는가.
- 화자·효과음 정보가 필요한 곳에 정확히 표시되는가. 자동 화자 라벨을 사람 이름으로 추측하지 않았는가.
- 무자막 마스터·교정 자막·화면 고정 자막의 버전을 구분했는가.
- 최종 인코딩 후에도 앞·중간·끝과 중요한 수치를 확인했는가.

YouTube는 기본 SRT의 일반 UTF-8 텍스트를 지원하고 스타일 마크업은 반영하지 않는다고 안내한다. SRT 업로드용과 화면에 고정하는 디자인 자막을 별도 산출물로 관리하는 이유다. 실제 업로드는 이번 조사 범위가 아니다. [YouTube 공식 자막 형식](https://support.google.com/youtube/answer/2734698?hl=en)

## 5. BGM·SFX와 시각 자산의 권리 선별 경로

| 소스 | 권장 용도와 기본 선택 | 라이선스·귀속 | Content ID·예외 | 자동 통과시키면 안 되는 것 |
|---|---|---|---|---|
| **직접 만든 자산** | 자체 간단한 효과음·도식·허용된 녹음 | 공동제작자·음성·샘플·폰트 등 입력 권리를 기록 | 외부 샘플·루프가 섞였다면 별도 확인 | “직접 편집했다”만으로 제3자 권리가 사라짐 |
| **YouTube Audio Library** | YouTube용 BGM·SFX의 우선 선별 후보 | 곡별 라이선스를 확인. CC 곡은 요구되는 귀속 문구를 설명란 등에 반영 | YouTube 공식 안내는 이 라이브러리 음원이 Content ID 권리자 클레임 대상이 되지 않는다고 설명. 다른 채널 이용은 곡별 조건 별도 확인 | 일반 YouTube의 “무료 BGM” 채널을 공식 라이브러리와 같게 취급 |
| **Freesound** | 필요한 짧은 SFX. CC0 우선, 귀속 가능한 CC BY 차선 | 개별 소리의 라이선스·버전·제작자·원본 URL 확인. BY-NC·구형 Sampling+는 기본 상업 경로에서 제외 | 공식 FAQ도 같은 소리가 다른 곡의 Content ID와 매칭되어 클레임이 생길 수 있음을 설명 | 사이트 전체가 무료이므로 모든 음원의 상업 이용·특정인 음성 복제가 허용된다고 추정 |
| **Openverse** | CC0·CC BY 후보를 발견하는 검색 경로 | 원본 제공자 페이지로 이동해 실제 개별 라이선스·귀속·권리를 재검증 | 검색 메타데이터나 자동 귀속 문구가 권리 확인을 보증하지 않음 | 검색 결과의 라이선스 필터만 보고 `CLEARED` 판정 |

## 6. 라이선스별 허용·차단을 분리한다

| 권리 표시 | 상업 콘텐츠의 기본 처리 | 필요한 확인 |
|---|---|---|
| CC0 / 명확한 퍼블릭 도메인 | 우선 후보 | 표시가 정확한지, 다른 사람의 음성·초상·상표·작품 권리가 남는지 |
| CC BY | 귀속·변경 표시를 이행할 수 있으면 후보 | 원본·저작자·버전·라이선스 링크·필요한 고지와 변경 내역 |
| CC BY-SA | 기본 자동 경로에서 보류 | 동기화·변형 결과에 적용할 동일조건변경허락 의무를 수용할 수 있는지 |
| CC BY-NC 계열 | 상품 판매·광고·수익화 파이프라인에서 제외 | 별도 권리자의 서면 상업 허락이 있는지 |
| CC BY-ND 계열 | 영상 동기화·변형 후 공개 경로에서 제외 | 별도 동기화·변형 허락이 있는지 |
| 자체 스톡 라이선스 | 개별 허용 범위와 금지 용도 확인 후 후보 | 플랫폼·광고·재배포·제3자 권리·증빙 조건 |
| 불명확·원본 삭제·권리 충돌 | 공개/판매 파생본 차단 | 다른 자산으로 교체하거나 명확한 허락 확보 |

CC 공식 FAQ는 **음악을 움직이는 영상에 맞춰 동기화하는 것을 CC 라이선스상 adaptation으로 본다.** 음악을 자르지 않았다는 이유로 ND 음악의 영상 동기화를 통과시키지 않는다. SA 음악도 영상과 결합할 때 필요한 조건을 검토한다. [Creative Commons 공식 FAQ](https://creativecommons.org/faq/#when-is-my-use-considered-an-adaptation)

CC BY는 적절한 귀속·라이선스 링크·변경 표시를 요구하며 보증이나 모든 부수 권리를 제공하지 않는다. CC0도 타인의 프라이버시·퍼블리시티·상표권을 없애지 않는다. [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/), [CC0 1.0](https://creativecommons.org/publicdomain/zero/1.0/), [CC BY-NC 4.0](https://creativecommons.org/licenses/by-nc/4.0/)

여기서 NC·SA·ND의 기본 보류는 HeoBrain의 상업 재사용을 위한 운영 선택이다. “교육용”, “출처 표기”, “아직 수익이 없음”이라는 문구를 개별 사용 허락의 대체물로 삼지 않는다. 공개 녹음의 재사용 허락과 특정인의 음성 복제·모델 학습 동의도 분리한다.

## 7. 자산 권리와 클레임 상태를 별도 장부로

기존 자산 정책의 `ASSET_LICENSE_MANIFEST.md` 원칙에 맞춰 **자산 한 개마다** 다음을 기록한다. 아래는 설계 필드이며 실제 확보 자산은 없다.

```json
{
  "asset_id": "example-only",
  "role": "bgm|sfx|video|image|voice",
  "title": null,
  "creator": null,
  "source_url": null,
  "original_asset_url": null,
  "license_name": null,
  "license_version": null,
  "license_url": null,
  "checked_at": null,
  "commercial_use_verified": null,
  "modification_and_sync_verified": null,
  "permitted_channels": [],
  "attribution_text": null,
  "actual_modifications": [],
  "voice_or_model_release": null,
  "third_party_rights": null,
  "evidence_paths": [],
  "download_certificate_path": null,
  "sha256": null,
  "clearance_status": "UNVERIFIED",
  "content_id_status": "NOT_CHECKED",
  "publish_allowed": false
}
```

귀속 문구의 설계 예:
```text
[작품명] — [저작자], [자산 원본 URL]
[라이선스명·버전] ([라이선스 URL])
변경: [실제 자르기·반복·믹스 등]
```

실제 라이선스가 요구하는 고지와 기존 변경 표시도 보존한다. 귀속 의무가 없는 자산도 내부 증빙은 남긴다. 검색 결과 URL만 저장하거나 원본 음원·영상 파일을 인계 문서 ZIP에 자동 포함하지 않는다.

### Content ID 예외 처리

1. 자산의 `clearance_status`와 채널의 `content_id_status`를 따로 기록한다.
2. 클레임이 발생하면 곡·구간·권리자·정책·원본 업로드/다운로드 증빙을 확인한다.
3. 허용 범위와 증빙을 검토한 뒤 플랫폼의 정식 절차 또는 자산 교체를 선택한다.
4. 이의제기·항소는 권리 주장을 수반하므로 자동 제출하지 않는다.
5. 클레임을 피하려고 피치·속도·음량을 바꾸는 경로를 만들지 않는다.
6. 원본 자산이 같아도 클레임 상태를 다른 채널의 성공 결과로 복사하지 않는다.

Pixabay는 Content ID 등록 곡에 인증서를 제공하며, 미등록 곡도 링크·파일명·라이선스 기록을 보관하도록 안내한다. 인증서는 자동 수익화·클레임 해제 보장이 아니다. [공식 Content ID·인증서 안내](https://pixabay.com/service/faq/)

## 8. loudnorm과 sidechaincompress는 서로 다른 일을 한다

| 기능 | 역할 | 쓰기 좋은 위치 | 해결하지 못하는 문제 |
|---|---|---|---|
| **sidechaincompress** | 두 번째 입력의 신호를 보고 첫 번째 입력을 압축 | 내레이션을 제어 신호로 삼아 BGM을 낮추는 ducking | 발음·사실 오류, 권리 문제, 전체 최종 음량 목표 |
| **loudnorm** | EBU R128 기반의 통합 음량·음량 범위·최대 true peak 조절 | 승인된 믹스의 측정과 최종 출력 정규화 | 목소리 명료도·과한 BGM·클리핑 전 원음 손상·자막 동기 |
| **ffprobe와 청취** | 스트림·길이·채널 정보 및 실제 소리 검수 | 입력과 최종 인코딩 양쪽 | 숫자만으로 내용·믹스 품질 자동 승인 |

`loudnorm`은 1회·2회 처리와 선형·동적 모드를 지원한다. 파일 작업에서는 먼저 측정값을 저장한 후 같은 믹스에 적용하는 2회 처리 후보를 둔다. 선형 모드의 조건을 충족하지 않으면 동적 모드로 돌아갈 수 있으므로 실제 결과의 모드를 기록한다. 동적 모드의 내부 업샘플링과 출력 샘플레이트 설정도 구분한다. [FFmpeg loudnorm 공식 문서](https://www.ffmpeg.org/ffmpeg-filters.html#loudnorm)

`sidechaincompress`는 첫 입력을 두 번째 입력으로 제어한다. 내레이션을 첫 입력에 넣고 음악으로 제어하면 의도와 다른 처리가 될 수 있다. threshold·ratio·attack·release는 실제 목소리·음악을 듣고 설정한다. [FFmpeg sidechaincompress 공식 문서](https://www.ffmpeg.org/ffmpeg-filters.html#sidechaincompress)

### 제안 처리 순서

```text
검수된 음성 원본 보존
  → 필요한 문장/쉼 편집과 실제 길이 확정
  → 권리 검증한 BGM·SFX의 구간·기본 게인 배치
  → 음성 신호로 BGM ducking
  → 음성 + 조절된 BGM + SFX 합성
  → 최종 믹스의 음량·true peak 측정
  → 승인한 출력 프로필로 정규화/인코딩
  → 최종 파일 다시 측정 + 실제 청취 + 자막 동기 확인
```

이번 조사에서 특정 LUFS·dBTP를 YouTube·쇼츠·릴스의 공식 의무값으로 확인하지 않았다. **고정 LUFS 수치를 플랫폼 필수 규격으로 적지 않는다.** FFmpeg 필터의 기본값도 플랫폼의 요구값이 아니다. 출력 목표는 확인한 납품 규격이나 명시한 내부 믹스 정책으로 관리하고, 실제 측정값과 별도 기록한다.

음악 없이도 정보 전달이 충분한 설명교육 편은 무음 BGM 경로가 기본 후보다. 휴대폰 스피커·이어폰·낮은 재생음량에서 숫자와 문장 끝이 들리는지 확인한다. 갑작스러운 효과음·펌핑·마지막 잘림·좌우 채널 문제는 측정 숫자만으로 통과시키지 않는다.

## 10. 첫 시험 체크리스트와 인계

아직 아래 시험은 실행하지 않았다. 기존 중립 한국어 대본·TTS 20문장을 재사용하고 개인 음성을 외부에 보내지 않는 범위로 설계한다.

### 입력과 자원

- [ ] 승인 표시 원고·발음용 문자열·합성 음성의 버전과 해시를 고정했다.
- [ ] 현재 RAM·가용 디스크를 읽기 전용으로 확인하고 동시 무거운 작업을 피할 시간대를 정했다.
- [ ] 작은 다국어 모델부터 CPU int8을 시험하며 실제 최대 RAM·처리시간·스왑·수정 분을 기록한다.
- [ ] 내부 배치 확대와 작업 대기열 순차 실행을 구분한다.
- [ ] 모델·정렬·화자 분리 구성요소별 버전·라이선스를 확인했다.

### 자막과 음향

- [ ] 음성의 실제 길이로 자막 시간을 만들었다.
- [ ] 중요한 숫자·고유명사·부정 표현을 원문과 실제 청취로 확인했다.
- [ ] BGM 없는 버전에서 먼저 내레이션을 통과시켰다.
- [ ] 음원 라이선스·허용 채널·귀속·동기화 권리를 확인했다.
- [ ] 작은 화면과 작은 재생음량에서 마지막 렌더를 확인했다.
- [ ] 목표 음량 프로필·측정 결과·클레임 상태·수용 원가를 분리해서 남겼다.

### 통합본에 반영할 범위

1. 12단계 중 장면/음성 기획과 렌더/품질 확인에 실제 음성 길이·자막 정렬·청취 검수를 연결한다.
2. 자산 권리 원장에 음원·효과음·채널별 허용 범위와 Content ID 상태를 추가한다.
3. 기본 모델 후보에는 faster-whisper를 CPU 시험 후보, WhisperX를 필요할 때만 쓰는 정렬 후보로 제시한다. 원본 35개 도구 ID는 그대로 둔다.
4. 가이드·인계 문서에는 후반작업 슬롯과 이 문서 링크를 추가할 수 있다. 운영 연결·실제 다운로드·외부 발행은 별도 실행·검증 항목이다.
